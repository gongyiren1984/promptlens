# 06 数据、版本与项目目录规范

## 1. 设计目标

项目数据必须满足：用户可选择位置、可整体备份、可迁移、可校验、可恢复；历史运行与报告不因继续编辑而变化；无需安装 Git 即可获得自动版本；未来可由云同步或外部工具安全读取。

## 2. 存储分层

| 层 | 内容 | 一致性要求 |
| --- | --- | --- |
| 项目清单 | 项目 ID、schema 版本、创建信息、校验信息 | 外部可识别，不含密钥 |
| 事务数据库 | 实体元数据、版本索引、状态、事件、评估结果 | SQLite 事务与 WAL |
| 内容对象 | 提示词文本、用例批次、原始请求/响应、报告、导出模板 | 内容寻址、不可变、写后校验 |
| 运行导出 | 用户可直接阅读的 Markdown、CSV/JSONL | 可重建，不作为唯一权威源 |
| 全局索引 | 项目路径提示、全局资产库版本 | OS 应用数据目录；可重建部分索引 |
| 凭据 | API Key、Token | OS 密钥链；永不进入项目 |

## 3. 项目目录结构

用户选择的项目根目录采用以下约定：

```text
<project-root>/
├── promptlens.project.yaml          # 轻量项目清单
├── .promptlens/
│   ├── db/
│   │   └── project.sqlite3          # 项目事务数据库
│   ├── objects/
│   │   └── sha256/
│   │       └── ab/cd/<full-hash>    # 不可变内容对象
│   ├── events/
│   │   └── 2026-11.jsonl            # 可选可审计事件导出
│   ├── recovery/
│   │   └── <timestamp>/             # 修复副本与诊断
│   ├── cache/                        # 可删除派生数据
│   └── project.lock                  # 运行时单写锁
├── exports/
│   ├── prompts/                      # 用户主动导出的提示词
│   ├── cases/                        # CSV/JSONL 用例
│   └── reports/                      # 按 Run 归档的 Markdown
└── README.promptlens.md              # 人类可读的目录说明
```

规则：

- `.promptlens/` 内文件属于应用管理；`.promptlens/cache/` 可随时清理。
- 根目录不应放大型缓存或模型权重。
- 用户主动编辑 `exports/` 不改变项目事实；应用再次导出时会检测冲突，不静默覆盖。
- 外部工具读取项目应通过 CLI/API 或版本化导出，不直接写入数据库。
- 项目清单使用 UTF-8、LF 换行，字段名使用稳定英文标识。

## 4. 项目清单

示例：

```yaml
schema: promptlens.project/v1
projectId: 01JBZ8YQ1R2S3T4V5W6X7Y8Z9A
name: 客服回复质量实验
createdAt: 2026-11-25T08:10:00Z
createdBy: promptlens/1.0.0
dataDirectory: .promptlens
minimumReaderVersion: 1.0.0
```

不放入清单的内容：

- API Key、访问 Token、Cookie。
- 绝对依赖的另一项目路径。
- 会频繁变化的运行统计。
- 未实现兼容策略的实验性字段。

读取未知高版本项目时，应用必须以只读模式打开或拒绝打开，并显示所需升级版本，不能猜测字段语义。

## 5. 内容对象规范

### 5.1 哈希与命名

- 规范化后的内容计算 SHA-256。
- 对象路径为 `objects/sha256/<前两位>/<后两位>/<完整哈希>`。
- 同一哈希只存一份；相同内容去重不改变业务引用。
- 文本规范化：UTF-8、LF 换行、去除仅由归档格式引入的 BOM、保留正文尾随空白的明确规定。
- 二进制响应按原始字节保存，同时对可提取文本创建规范化派生对象。

### 5.2 写入协议

1. 写入同目录临时文件。
2. `flush/fsync`。
3. 计算哈希并校验长度。
4. 目标不存在时原子 rename；已存在时校验相同哈希。
5. 在数据库事务中登记引用。
6. 定期清理未被数据库引用的孤儿对象。

读取对象时必须校验哈希。校验失败时标记对象损坏，从备份或用户导出副本恢复，不继续把损坏内容用于运行。

## 6. SQLite 使用规则

- 开启 WAL、外键和合理的 `busy_timeout`。
- 一个核心服务为写者，桌面/CLI/MCP 不直接写库。
- 迁移前执行 `PRAGMA integrity_check` 并创建完整项目备份。
- 大文本和大响应不存 BLOB，只存对象哈希和必要摘要。
- FTS5 索引只存非敏感可搜索摘要；敏感用例字段需要用户显式同意后才建立全文索引。
- 常用查询建立复合索引，例如 `runs(project_id, status, created_at)`、`trials(run_id, model_config_version_id, status)`。
- 聚合统计可存派生表，但必须能从事实表重建并标记构建版本。

## 7. 版本管理模型

### 7.1 版本类型

| 对象 | 版本策略 | 版本号 |
| --- | --- | --- |
| Prompt | 被保存/引用时生成，不可变 | 项目内单调递增 |
| Case | 内容修改后生成 | 用例内单调递增 |
| Test Set | 用例版本集合或抽样策略变化后生成 | 测试集内单调递增 |
| Evaluation Profile | 任一维度、规则、权重、评审模型变化后生成 | 方案内单调递增 |
| Model Config | 参数、价格依据、重试策略或 fallback 变化后生成 | 配置内单调递增 |
| Run Snapshot | 每次启动 Run 生成 | Run 内版本 1 |
| Report | 每次按模板或评估结果生成 | Run 内单调递增 |
| Report Template | 章节、变量或语言变化后生成 | 模板内单调递增 |

### 7.2 版本不可变性

- 已保存版本不可就地编辑。
- “恢复版本 N”生成 N+1 的内容副本，并记录 `restoredFromVersionId`。
- 删除逻辑对象时，历史 Run 对版本的引用仍可读取；物理清理只能在用户选择“清理无引用版本”后执行。
- 报告必须能对应到快照哈希和评估版本，而不是指向一个可漂移的“最新版”。

### 7.3 自动版本触发

必须生成的时点：

- 提示词被加入 Run。
- 用例/测试集被加入 Run。
- 评分方案被加入 Run。
- 模型参数被加入 Run。
- 报告生成。
- 跨项目库复用。

草稿可以细粒度自动保存，但不会污染正式版本历史；界面明确显示“草稿”与“已保存版本”。

## 8. 运行快照

快照是一个自包含 JSON，至少包含：

- schema 与 appVersion；
- projectId、runId、parentRunId；
- 每个 PromptVersion 内容哈希；
- TestSetVersion 与全部 CaseVersion 哈希；
- ModelConfigVersion、Provider adapterVersion、能力快照；
- 对话策略、终止条件、最大轮数；
- EvaluationProfileVersion 和评审 Prompt 哈希；
- 预算上限、采样种子、重复次数；
- 报告模板版本；
- 全部配置的规范化哈希 `specHash`。

快照不得只保存“当前提示词 ID”这类间接引用。机器可读示例见 [experiment-spec.schema.json](../schemas/experiment-spec.schema.json)。

## 9. 成本数据

### 9.1 用量

每次 Attempt 保存：

- 输入 Token、输出 Token、缓存命中 Token（若 Provider 提供）、推理/思考 Token（若单独计费）；
- 原始用量对象和适配器解析版本；
- 估算值与实际值；
- 币种、价格表 ID、价格表版本及生效时间。

### 9.2 金额

```text
attempt_cost = input_tokens × input_unit_price
             + output_tokens × output_unit_price
             + other_billable_units × unit_price
```

- 未知字段保持 `unknown`，不使用 0 代替。
- Run 聚合同时报告“已知金额合计”和“未知价格请求数”。
- 系统只做成本估算，不代替 Provider 账单；报告明确说明估算口径。
- 历史价格表不因 Provider 调价而改写。
- 价格表结构见 [pricing.schema.json](../schemas/pricing.schema.json)；每张表必须有 `priceTableId`、`version`、`effectiveFrom`、`currency` 与来源。
- 跨币种换算必须记录 `fx` 依据（汇率、基准币种、报价币种、生效时间、来源）；未配置汇率时保持原币种并标记“未换算”，不做隐式换算。
- 金额计算使用十进制定点或高精度整数，禁止二进制浮点；舍入规则固定为“先按请求累计、最后按币种最小单位四舍五入”，并在报告中注明。

## 10. 事件与审计

采用“当前状态 + 追加事件”的组合，不实施完整事件溯源：

- 当前状态表支持快速查询。
- `RunEvent` 记录领取、Attempt、进度、停止、完成等顺序事件。
- 审计事件记录项目创建/迁移/删除、密钥引用变更、Run 启动/停止、报告导出、Agent 写操作。
- 事件只追加，敏感值先脱敏。
- 事件缺失时可用状态和对象校验修复，但不伪造事件。

## 11. 备份、迁移与恢复

### 11.1 备份

用户可创建 `.promptlens-backup` 归档，包含：

- 项目清单；
- 数据库一致性副本；
- 被引用对象；
- 报告与清单；
- 校验清单和 schema 版本。

不包含系统密钥链凭据。恢复后用户需重新授权凭据。

### 11.2 目录迁移

1. 预检目标空间、权限、文件系统大小写和锁状态。
2. 暂停写操作但允许读取当前项目。
3. 复制到目标临时目录并校验。
4. 原子切换项目绑定。
5. 保留旧目录只读副本并提示用户确认删除。

跨卷或同步盘不支持原子 rename 时，以清单中的项目 ID 和校验结果验证，不使用绝对路径作为身份。

### 11.3 崩溃恢复

- 启动时检查 WAL 与锁状态。
- 运行数据库 `quick_check`；必要时执行完整检查。
- 校验所有被引用对象是否存在且哈希匹配。
- 将未登记临时对象移入恢复区。
- 把最后状态为 `running` 的 Trial 标为需核验，不直接判定成功。
- 生成恢复报告，记录自动采取的动作。

### 11.4 降级限制

新版本迁移后的项目默认不能由旧版本写入。旧版本可只读展示兼容字段，或提示用户导出后升级；应用不得通过删除新字段实现“降级”。

## 12. 数据清理与保留

| 数据 | 默认保留 | 用户可配置 |
| --- | --- | --- |
| 项目资产与版本 | 永久，除非用户删除 | 清理无引用版本 |
| Run 快照与报告 | 永久 | 归档/导出后清理 |
| 原始模型响应 | 永久 | 按天数或存储量清理 |
| 日志 | 30 天 | 级别与期限 |
| 缓存与临时文件 | 可重建 | 随时清理 |
| 审计事件 | 项目生命周期 | 企业策略导出 |

清理原始响应后，报告中的证据会标记“证据已清理”，评估摘要仍可读。系统不得假装证据仍存在。

审计事件与日志是两类数据，不得互相替代：

- 审计事件存于项目数据库的追加表，随项目生命周期保留，可导出；删除项目或清理审计属于高危操作，必须显式确认并追加新的审计事件。
- 日志是运行诊断，默认保留 30 天，可随时清理；清理日志不影响审计可追溯性。
- 报告、CLI/MCP 输出和备份清单必须能区分“审计记录缺失”和“证据已清理”两种状态。

## 13. 全局数据目录

OS 应用数据目录保存：

- 工作区项目路径索引；
- 全局模型连接元数据和密钥链引用；
- 全局用例库快照与来源；
- 用户界面偏好；
- 本地服务地址、凭证与日志索引。

该目录不是项目内容副本。全局库资产采用不可变快照，复制到项目后成为项目数据的一部分。
